# FocusDesk — tasks and focus sessions

An offline Electron desktop app with **Tasks**, **Timer**, **Stats**, and **Obsidian** pages. It includes persistent tasks, focus sessions, optional breaks, completed-session history and a day/week/month bar chart. Data persists locally, with append-only Markdown task/focus events in a selected Obsidian vault. See [PRD](docs/PRD.md) for the full scope.

## Run in VS Code

1. Install Node.js and npm. Open this repository folder in VS Code (**File → Open Folder**).
2. Open **Terminal → New Terminal**. Run `npm ci` to install Electron (internet required for the first install; using the installed app afterward is offline).
3. Run `npm start`. Stop with Ctrl+C in the terminal. On macOS, closing the window can leave Electron running; use its Quit menu or Ctrl+C.
4. Click **Obsidian** in the top right, then **Choose vault folder** and select the **root of an existing Obsidian vault** (the folder containing `.obsidian`). If needed, create one in Obsidian first. FocusDesk writes new files under `<vault>/FocusDesk/tasks/` and `<vault>/FocusDesk/focus/`; it does not rewrite older event files. Open `<vault>/FocusDesk/Overview.md` in Obsidian for a task-grouped, linked history. FocusDesk refreshes this derived overview from event files when the app opens or writes an event.

`npm test` runs the automated storage/timing checks. No account or cloud service is needed while running.

## Use the app

- **Obsidian:** See the selected vault and pending event count, choose a vault folder, and retry pending events after restoring an unavailable vault. A numbered badge on the Obsidian button warns you when events have not been logged yet. Resolve pending events for their original vault before switching folders.
- **Tasks / Home:** Add a title and, if you like, expand **Optional details & suggested times** before saving to enter a description, suggested focus (25 minutes by default) and suggested break (10 minutes by default). For a new task, changing focus above 25 minutes suggests the configured long break (30 minutes initially); you can still enter a custom break. Each task card has **Focus**, **Edit** (including these fields and colour), **Complete/Reopen**, and **Delete** (with confirmation). Older tasks without suggestion fields still show 25/10; existing saved task data is not rewritten just by viewing it. Marking a task Complete shows a completion popup. When a linked focus timer reaches zero, its open task is marked Completed and can be reopened; Finish early leaves the task open.
- **Timer:** Click a task's **Focus** button to open Timer with the task selected and its suggested lengths shown. You can change focus and break minutes (1–180 whole minutes) for this session without changing the task. Alternatively expand **Focus on another activity** and enter a short description; Start remains disabled without a task or description. **Pause** stops counting time; **Resume** continues. **+5 minutes** is available once per session. **Finish early** saves measured active time; reaching zero does the same automatically. **Stop / Cancel** asks for confirmation and does not add partial time to completed-session history.
- **Close and reopen:** A running or paused session becomes **Interrupted**. On reopening, choose **Resume** or **Cancel interrupted session**; time while the app was closed is not counted. After an unexpected crash, up to roughly one second of recent active time may be lost because the app checkpoints once per second. It never silently completes a recovered session.
- **Breaks:** The Timer's break length is used for the optional break after that session. FocusDesk shows a reminder on Timer shortly before focus ends and a completion popup with **Start break** or **Later** when focus ends. The optional break offer stays on Timer; it does not show a banner on Tasks / Home. FocusDesk also attempts a desktop warning shortly before focus ends. On macOS, notifications from an unsigned development build may not display, so use the in-app Timer reminder as the reliable warning. If you reopen the app with an unused break offer, it remains on Timer without reopening the popup. Expand **Default short & long break lengths** to change the 10/30-minute defaults. Sessions started without a per-session break override use short for plans of at most 25 minutes and long otherwise. Start shows a countdown; Finish or Stop ends the break. Closing the app pauses a running break at the last saved checkpoint; reopen and press Resume. Breaks are local-only, with no vault break events or completed-focus history entries. A 30-minute focus followed by a 10-minute break uses 40 minutes on the clock, but Stats records only 30 minutes of focus.
- **Stats:** Completed focus sessions show actual active seconds and local completion time; they survive restart. Cancelled sessions are not listed. Task titles are snapshotted when focus starts, so editing or deleting a task does not relabel earlier sessions. Choose Day, Week, or Month for horizontal bars of actual completed focus time by task; description-only sessions are grouped under **Other activities**. The week begins Monday in your computer's local timezone. Current task names appear even when renamed; deleted tasks keep their last saved session title. Breaks and cancelled sessions are excluded.

## Short manual test

1. Select a vault and add `Read chapter 3`. Expand the optional details to add a description and suggested 1-minute focus / 2-minute break. Click its **Focus** button: Timer should show this task and 1/2. Change the break to 3 minutes for this session, Start, wait briefly, Pause, wait several seconds, Resume, then Finish early. On **Stats**, check the actual active seconds (less than a minute), the task remains Open on **Tasks / Home**, and `FocusDesk/focus/` has one `focus-start` and one `focus-completed` `.md` event with matching session ID, task ID/title snapshot, date/time/timezone, and actual active duration. The break offer should use 3 minutes; the task suggestion should remain 2.
2. On Timer, choose no task, expand **Focus on another activity**, type `Review notes`, Start, then **Stop / Cancel**. Check the confirmation and that no completed-history row is added on Stats. A `focus-cancelled` event should appear.
3. Start a 1-minute session linked to an open task and let the timer reach zero. Check the task changes to Completed, the break prompt appears, the history row shows actual focused time, and the vault has one focus-completed and one task-completed event. Choose Later; the break offer should remain on Timer. For the extension, start a separate session, click **+5 minutes** once, and check the button disappears and the remaining time grows; Finish early to avoid waiting.
4. Start a session and close the window while it runs. Reopen the app: it must say **Interrupted** and offer Resume or Cancel, without adding closed-app time. Resume and Finish or choose Cancel. Check the history and events accordingly.
5. To test logging failure, rename the vault folder while a session is running, then Finish. The local history should remain, with a numbered warning on **Obsidian**. Open that page to see pending events. Restore the **original folder name**, click **Retry pending events** there, and check the focus event appears once. Pending events block switching vaults.

6. On Timer, set the break field to **1** minute, complete a focus session early, and check the completion popup offers Start break or Later. Choose Later and confirm the break offer remains on Timer, without a break banner on Tasks or Stats. Start it, watch the countdown decrease, then Finish. Repeat with a **2**-minute break after a longer plan; Start and Stop it. Check the focus-history rows and active seconds did not change while breaking. Close/reopen during another break: it should be paused and offer Resume, without counting time closed. The expandable short/long defaults apply when no per-session override is supplied.
7. Complete focus once for each of two tasks and once for a description-only activity. In **Stats**, check the bars and totals for Day, Week, and Month. Rename one task: its earlier focus time should stay in the same bar. Delete a task only if it is disposable; its completed time should remain in the report.

## How it fits together

`src/main.js` owns the window, folder picker, one-second checkpoint timer and close handling. `src/preload.js` exposes only named actions to the page. `src/index.html`, `src/style.css`, and `src/renderer.js` display and operate the four pages. `src/report.js` totals completed focus sessions by local date and task ID. `src/store.js` saves state in Electron's app-data `state.json` and queues vault events before writing them as new files. Task suggestions are optional fields on each task; a session copies the selected lengths when started, so adjusting its timer does not edit the task. `tests/store.test.js` covers tasks; `tests/focus.test.js` and `tests/break.test.js` use controllable clocks to verify timing without long waits; `tests/report.test.js` covers period and grouping rules. `package-lock.json` pins dependency versions for repeatable installs.

## Limits

The chart shows the current day, week or month; earlier periods are not selectable in this version. Breaks are locally saved countdowns, not recorded sessions or Markdown events. A vault must contain `.obsidian`. If vault logging fails, task or session changes remain locally saved, but pending events must be retried for their original vault before switching. Keep backups of your app data and vault; this is student-project software. Native folder-picker click-through and a disconnected-network run still need user-run manual checks.
