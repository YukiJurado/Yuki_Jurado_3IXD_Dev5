# Implementation notebook — first working slice

## Decisions
- Followed the already-confirmed PRD/Grill decisions; no new product scope. Task cards and add action take their cue from Task-List-Sketch; timer and stats sketches are reserved for later stages.
- Plain JavaScript + Electron, with a sandboxed page and a narrow preload API. The Electron main process alone performs file I/O.
- Local `state.json` contains tasks, selected vault, and pending events. A temporary file is renamed into place for each save. The vault receives a unique `.md` file per event via exclusive creation; retry checks an existing file's exact contents before clearing a pending event.
- The app requires a selected folder containing `.obsidian`. Missing vault writes do not recreate a fake vault folder. Pending events stay associated with the original vault and block switching.

## Focus-session milestone
- Design: the Electron main process owns the timer and checkpoints active milliseconds to local JSON once per second. Pausing freezes that total. The UI displays a countdown derived from the stored active total plus the current running segment; it does not decide when a session finishes. A completion stores actual active milliseconds and a task ID/title snapshot or activity description; it does not change task status. Stop cancels and logs but excludes partial time from completed history. A single +5 extension changes planned time, not measured time.
- Close/recovery: normal window close checkpoints and marks the session interrupted; startup also converts a still-running/paused checkpoint after an unexpected exit to interrupted, discarding any time since the last checkpoint. Resume or Cancel is offered, not automatic completion. Running/paused session switches to another vault are blocked; pending events keep their original vault and use the existing exclusive-write retry.
- TDD: focus storage tests were red before each implementation slice for start/cancel, pause/manual finish, configurable length/auto finish/extension, interruption/recovery, and unavailable-vault retry. A boundary regression test caught Stop cancelling a session whose zero point arrived just before the timer tick; Stop now checks for automatic completion first. `npm test` passed **18/18** after integration with the prior task tests. A fake clock measured exact pause-excluded durations and one-minute automatic completion.
- Electron UI smoke with an isolated fixture vault: a task-linked session used Start, Pause, Resume, +5 and Finish; the saved completed duration was **1287 ms**, and the task stayed Open. A description-only session was cancelled, leaving history at one entry and producing a cancellation event. The vault had four focus event files at that point. A real one-minute description session then auto-completed at **60000 ms**; persisted history and a subsequent UI probe showed it, with six focus event files total. The first automatic-smoke script hit a timing race reading the renderer immediately after the JSON update and timed out; the on-disk state and a separate CDP page probe confirmed completion and visible history, not a fabricated pass.
- Unexpected-exit smoke: started a session, captured a checkpoint, terminated Electron, restarted using the same isolated app-data folder, and observed the Interrupted message and Resume control. Resuming then finishing increased the stored active time from **11934 ms** to **13137 ms**, without adding the time between processes. The normal close hook was covered by fake-clock tests; a native OS window-close gesture was not separately automated.
- Limitations: no breaks or chart in this milestone; the native vault picker still needs manual user confirmation because desktop automation permission is pending.
